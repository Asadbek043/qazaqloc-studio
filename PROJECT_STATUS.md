## Что представляет собой проект

Существующая веб-платформа QA локализации игр EN/RU → KK. Работает на Windows из VS Code без хостинга, Docker, MySQL и phpMyAdmin. Веб-интерфейс и отдельный CLI используют один Python LocQA Core. Анализ правил и глоссарий доступны без ИИ.

Основной локальный режим: FastAPI обслуживает frontend/dist и API на 127.0.0.1:8000; SQLite в data/qazaqloc.db. Dev-режим: Vite обычно 5173 проксирует /api на FastAPI:8000. SQLite не запускается отдельным сервисом.

## Связи и важное поведение

- Веб загружает имена и тексты файлов JSON-телом PUT /api/projects/{id}/files, не multipart. POST analyze вызывает общие парсеры и analyze, затем при запросе with_ai; результат и run_id сохраняются в проекте.
- Перед повторным анализом к исходному переводу применяются текущие неотклонённые edits. Загрузка новой пары сбрасывает активные edits и report, но сохраняет предыдущие runs/history.
- PUT edit валидирует ключ, версию и роль; `save` → not_reviewed, `submit`/`revise` → needs_revision, `approve` → human_approved, `reject` → human_rejected.
- Экспорт отчёта дополняется актуальными review-записями; количество проблем остаётся от последнего анализа. После редактирования нужно запускать анализ повторно.
- CLI не требует серверной БД/аккаунта, создаёт JSON/HTML. Редакторские ARB/audit и ZIP доступны через веб/API; отдельной CLI-команды для них пока нет.
- Значения .env не переносить в документы. Здесь достаточно имён AI_API_KEY / AI_BASE_URL / AI_MODEL / DATABASE_URL / PORT. ИИ по умолчанию выключен; его отсутствие не блокирует остальное.

## Известные ограничения и незавершённые задачи

Критических воспроизводимых отказов основных сценариев в текущем pytest не обнаружено. Это не утверждение, что весь первоначальный объём ТЗ завершён.

- **Язык:** нет независимой вычитки носителем, подтверждённого глоссария, полной морфологии или полной проверки грамматики/контекста без ИИ. UI-словари также требуют вычитки.
- **ИИ:** живые вызовы и качество провайдера не проверены. Инструкция просит объяснения на KK даже при RU-интерфейсе; нет автоматического перевода объяснений. Индикатор наличия ключа не проверяет его валидность.
- **ICU/ARB:** собственный парсер — подмножество; крайние apostrophe/skeleton-случаи и полная семантика metadata/типов Flutter не покрыты. HTML-атрибуты не сравниваются отдельными правилами.
- **Экспорт:** ещё нет режима «только одобренные». Ручные сохранённые правки могут экспортироваться без human_approved. Неразрешённые ошибки исходного перевода остаются; `_fixed` не гарантирует готовности.
- **Рецензирование:** нет политики независимого второго человека, администратор может одобрять своё. Общая команда, не multi-tenant; qualifications — ручные сведения.
- **UI/локализация:** часть технических ошибок/HTML-заголовков не переведена; preview не интегрирован с настоящей игрой. Автооткрытие браузера по умолчанию требует подтверждения на компьютере пользователя.
- **Масштабирование:** JSON payload в SQLite, синхронный анализ, без фоновой очереди и больших нагрузочных измерений; отдельного слоя миграций нет.
- **Git:** первоначальная версия сохраняется по прямому разрешению пользователя. БД/.env/artifacts намеренно игнорируются и требуют отдельного резервирования/регенерации; локальная история не заменяет внешнюю резервную копию.
- **Доказательства:** исторический audit и малая evaluation-выборка не доказывают общую точность и будущую совместимость всех версий.

## Ближайшие приоритеты (согласовать задачу перед реализацией)

1. Получить от пользователя подтверждение, что двойной клик открывает сайт; при проблеме воспроизвести именно Windows default browser, не менять дизайн/зависимости вслепую.
2. Для следующих задач сохранять полезные версии отдельными коммитами только по разрешению пользователя; первый коммит уже отдельно разрешён. Не настраивать remote и не публиковать проект автоматически.
3. Подготовить независимую вычитку KK-интерфейса, глоссария и исправлений настоящим рецензентом; обеспечить реальные audit-записи.
4. Проверить live AI только при доступном ключе и согласованном использовании данных; без этого продолжать остальные задачи.
5. По отдельному поручению закрывать пробелы ICU/ARB и тестов на независимых файлах; расширить evaluation по категориям, не подменяя baseline.
6. По отдельной задаче: экспорт только одобренных, полная служебная локализация, нормализованное хранение/очередь для больших проектов. Это план, не уже существующая функциональность.
